# compat-edges.jsonl — compatibility claims extracted from crash reports

> ROADMAP 1A.2 · the seed data pipeline for the Compatibility Graph
> (VISION product line 5). **Record-only**: nothing queries this file yet.
> Generated by `tools/build_compat_edges.py`; reproducible — never edit by hand.

Each line is one aggregated **CompatibilityClaim** (VISION §4.3), deduped by
`(subject, object, relation, loader, mc_version)`:

```jsonc
{
  "subject": "mekanism",            // the mod the claim is about
  "object": "mekanism",             // for caused/suspected: same as subject.
                                    // for co_occurred: the mod that was blamed
  "relation": "caused",             // caused | suspected | co_occurred
  "loader": "forge",                // loader at crash time (nullable)
  "mc_version": "1.20.1",           // MC version at crash time (nullable)
  "mod_version": "10.4.5.19",       // subject's version if the Mod List had it
  "evidence_count": 3,              // how many distinct reports back the claim
  "source_reports": [               // up to 5, for traceability
    {"repo": "mekanism/Mekanism", "issue": 8590,
     "url": "https://github.com/mekanism/Mekanism/issues/8590"}
  ],
  "maintainer_verdict": "bug_in_this_mod",  // weak supervision from issue
                                            // labels, when a maintainer set one
                                            // (nullable; see corpus/README)
  "confidence": 0.97,               // best attribution confidence seen
  "sample_evidence": "stack frame #12: mekanism.common....",
  "first_seen": null,               // reserved for the query layer
  "last_seen": null
}
```

## Relations

| relation | meaning | signal strength |
|---|---|---|
| `caused` | subject was the **top** attribution for a crash — the game's own first-listed `Suspected Mods` entry when present (confidence 0.95), else our triage top-1 | strong |
| `suspected` | subject was a secondary suspect (ranks 2–4) | medium |
| `co_occurred` | subject was **present** (Mod List) in a report where `object` was blamed | weak — presence only, NOT guilt. In a 241-mod pack every mod co-occurs with every crash; the useful quantity is the pairwise *lift* over baseline presence rates, computed by a future query layer |

## Provenance & privacy

- Input: `corpus/github/` (gitignored raw harvest) joined to
  `corpus/index.jsonl` (committed, redacted) by repo/issue number.
- Output contains **no text from the reports** — only mod ids, versions,
  loader/MC versions, issue URLs and maintainer labels. Mod ids and version
  numbers are public package metadata, not PII.
- Regenerate after any corpus re-harvest:
  `python tools/build_compat_edges.py` (~10 min for 454 fragments;
  triage runs per report).

## Deliberate non-goals (for now)

- No graph queries, no visualization, no lift computation — VISION puts
  those in phase 2 (2027). This file is the accumulation that makes them
  possible.
- No cross-repo identity resolution (`mekanism` vs `Mekanism` — mod ids are
  already lowercase-normalized by the parser).
- `first_seen`/`last_seen` stay null until a query layer needs them.
